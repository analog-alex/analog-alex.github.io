# AGENTS

## Stack and Source of Truth
- This is a plain Zola site (no Node/Python/Rust package manifests, no task runner).
- Primary config is `config.toml`; Sass compilation is enabled (`compile_sass = true`).
- Deployment behavior is defined in `.github/workflows/zola-builder.yml` (push to `main` triggers deploy to `gh-pages`).

## Project Shape
- `templates/` contains all page templates; `templates/base.html` is the shared layout with header/footer/theme toggle.
- `content/` holds Markdown content and section front matter (`_index.md`).
- `sass/style.sass` is the single stylesheet source; output CSS is generated by Zola.
- `static/` contains copied assets (icons, fonts, images) served as-is.

## Content Conventions That Matter
- Blog section wiring is in `content/blog/_index.md`:
  - `template = "blog/blog.html"`
  - `page_template = "blog/blog-page.html"`
- Blog index template groups posts by `year` (`section.pages | group_by(attribute="year")`), so each blog post should keep a `year = <int>` front matter field.
- Posts are ordered by `date` because `sort_by = "date"` is set in `content/blog/_index.md`.

## CI/Deploy Constraints
- Workflow uses `shalzz/zola-deploy-action@v0.17.2`.
- It expects to push built output to `gh-pages` using `secrets.GITHUB_TOKEN`; workflow permissions must include `contents: write`.

## Practical Editing Notes
- Do not commit `public/` (ignored in `.gitignore`); it is a build artifact.
- Prefer updating templates/content/Sass directly; there is no repo-local lint/test pipeline to run.
